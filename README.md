# Datastraw Support Ticketing CRM

Full-stack customer support ticketing system built for the Datastraw Technologies intern assessment.

## Live Links
- **Live App:** https://datastraw-crm-kappa.vercel.app
- **GitHub Repo:** https://github.com/mrunal-awate/datastraw-crm
- **Backend API:** https://datastraw-crm-7euo.onrender.com

> Note: the backend is hosted on Render's free tier, which spins down after inactivity. The first request after a period of no traffic may take 30-60 seconds to respond while the server wakes up. This is expected, not a bug.

## Stack
- **Frontend:** React + Vite, Tailwind CSS, React Router
- **Backend:** Node.js + Express
- **Database:** Supabase (PostgreSQL)
- **Deployment:** Vercel (frontend), Render (backend)

## Features
1. Create tickets with customer name, email, subject, and description (ticket ID and timestamp auto-generated)
2. List all tickets with ID, name, subject, status, and date
3. Live search across customer name, email, ticket ID, subject, and description
4. Filter tickets by status (Open / In Progress / Closed)
5. Ticket detail view with status updates and notes/comments

## Architecture Notes
- The frontend never talks to Supabase directly — all requests go through the Express API. The backend uses Supabase's `service_role` key, which is kept server-side only.
- Ticket IDs (e.g. `TKT-001`) are generated by a Postgres sequence + trigger, not application code, so duplicate IDs are impossible even under concurrent requests.
- CORS on the backend is restricted to the deployed frontend origin (`FRONTEND_URL` env var) plus localhost for development — not open to all origins.

## API Endpoints
| Method | Endpoint | Description |
|---|---|---|
| POST | `/api/tickets` | Create a new ticket |
| GET | `/api/tickets?status=&search=` | List tickets, optional status filter and search |
| GET | `/api/tickets/:ticketId` | Get a single ticket with its notes |
| PUT | `/api/tickets/:ticketId` | Update status and/or add a note |

## Local Setup Instructions

### 1. Database (Supabase)
1. Create a project at https://supabase.com (or use an existing one)
2. Go to SQL Editor → paste and run `supabase/schema.sql`
3. Go to Settings → API → copy your **Project URL** and **service_role key** (not the anon key)

### 2. Backend
```bash
cd backend
npm install
cp .env.example .env
# edit .env with your Supabase URL, service_role key, and (optionally) FRONTEND_URL
npm run dev
```
Server runs on http://localhost:5000

### 3. Frontend
```bash
cd frontend
npm install
cp .env.example .env
# edit .env if your backend runs somewhere other than localhost:5000
npm run dev
```
App runs on http://localhost:5173

## Known Limitations / Improvements With More Time
- No email format validation on the create ticket form (accepts any text)
- No authentication — intentionally skipped for MVP scope per the assignment's own guidance
- Render's free-tier cold start adds latency on the first request after idle time
- Could add pagination if ticket volume grows large; current implementation loads all matching tickets in one query
